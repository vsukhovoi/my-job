# Telegram Bot Roadmap — `@myjob_in_bot`

**Проєкт:** My Job (myjob.co.ua)
**Дата створення:** 22.05.2026
**Статус:** Стратегічний план розширення функціоналу
**Часові рамки:** Довгострокова roadmap (без жорстких дедлайнів)

---

## Стратегічна рамка

**Принцип:** бот = другий повноцінний інтерфейс платформи. Сайт залишається основним для складних дій (створення вакансії, редагування резюме), бот закриває **~80% денних рутинних дій** — перегляд, реакції, швидкі відповіді.

**Конкурентний контекст:** жоден з основних українських job-платформ (Work.ua, Robota.ua, Djinni) не має повноцінного двостороннього інтерактивного бота. Це справжня unique selling proposition для My Job.

**Пріоритети (за порядком важливості):**
1. Конкурентна перевага (фічі, яких немає у конкурентів)
2. Утримання користувачів (engagement)
3. Монетизація (платні фічі через бот)
4. Зменшення навантаження на сайт

## Поточний стан (станом на 22.05.2026)

### Команди
- `/start` — вітання, deep link для вакансій/авторизації
- `/alerts` — підписка/відписка на категорії вакансій

### Авторизація
- Користувач натискає "Увійти через Telegram" на сайті

- `TelegramAuthController` + `TelegramAuthService` — генерація сесії, polling статусу

### Активні сповіщення

- **Кандидату:** зміна статусу заявки
- **Розсилка вакансій (щогодинна):** `SendVacancyAlerts` — нові вакансії підписникам по категоріях

## ФАЗА 1 — Закриття TODO + фундамент

**Мета:** передумова для всіх наступних фаз. Без цього не можна йти далі.

**Складність:** Низька
**Ефект:** Фундамент

### 1.1. Listener'и асинхронних співбесід
- `NotifyInterviewRequestSent` → кандидату з кнопкою «Відповісти»
- `NotifyInterviewResponseSubmitted` → роботодавцю з кнопкою «Переглянути»
- Врахування `notification_channel` preference (`prefersTelegram()` + наявність `telegram_id`)
- Feature-тести (відправка через Telegram / fallback на email / skip без `telegram_id`)

### 1.2. Розширення `TelegramNotifier` сервісу
- Підтримка inline keyboard (зараз тільки send-message)
- Підтримка callback_query handlers
- Edit message API (для оновлення статусу повідомлення in-place)
- Парсимо update'и в Python-боті → передаємо в Laravel через webhook endpoint

### 1.3. Стандартизація callback_data протоколу
- Формат: `action:resource_type:resource_id:param` (наприклад `apply:vacancy:123`, `extend:vacancy:123:30`)
- `TelegramCallbackRouter` — диспетчер у Laravel, який мапить callback_data на handlers
- **Захист:** підпис HMAC у callback_data щоб уникнути підробки
- Rate limiting на callback queries (анти-спам)

### Артефакти Фази 1
- Розширений `TelegramNotifier` (методи: `sendWithKeyboard`, `editMessage`, `answerCallbackQuery`)
- Новий `TelegramCallbackRouter` сервіс
- Webhook endpoint `/api/telegram/webhook` для callback queries
- `TelegramCallbackHandlerInterface` для уніфікації handler'ів

## ФАЗА 2 — Кандидат: швидкі дії

**Мета:** перетворити бот на основний канал для кандидата в денному використанні.

**Складність:** Середня
**Ефект:** 🟢🟢🟢 Engagement, 🟢🟢 Конкурентна перевага, 🟢🟢 Розгрузка сайту

### 2.1. Розширення `/alerts` — інтерактивна підписка
**Зараз:** підписка тільки на категорії
**Стає:** підписка на категорію + місто + зарплатний рейндж + тип зайнятості + remote
- Wizard у боті: послідовні питання з inline keyboard
- Multiple alert profiles («Київ Junior PHP», «Remote QA», «Дніпро дизайн до 30к»)
- Можливість редагувати/видаляти існуючі профілі
- Опційно: налаштування частоти (миттєво / щогодини / щодня)

### 2.2. Швидкий відгук з повідомлення розсилки
- Inline button `📨 Відгукнутись` на повідомленні про вакансію
- **Якщо resume повне:** відгук одним кліком → `editMessageText` → «✅ Відгук надіслано»
- **Якщо неповне:** кнопка веде на сайт з deep link на конкретний крок дозаповнення
- Кнопка `⭐ Зберегти` поряд

### 2.3. `/applications` — мої відгуки
- Список останніх 10 відгуків з статусами (іконки за `ApplicationStatus` Enum)
- Inline по кожному: «📄 Вакансія», «🗑 Видалити»
- Pagination через callback (`prev` / `next` / номер сторінки)
- Фільтр по статусу

### 2.4. `/saved` — обрані вакансії
- Збереження вакансії з розсилки (button `⭐`)
- Окрема команда для перегляду збережених
- Швидке порівняння (до 3 вакансій side-by-side)

### 2.5. Сповіщення про переглянуте резюме (privacy-aware)
- Коли роботодавець відкриває резюме → опційне push-сповіщення кандидату
- Контроль privacy: toggle у `/settings`
- За замовчуванням **вимкнено** (privacy by default)

### Артефакти Фази 2
- 4 нові команди (`/applications`, `/saved`, `/settings`, розширення `/alerts`)
- Нові callback handlers: `apply`, `save`, `unsave`, `delete_application`
- Нові таблиці: `vacancy_saves`, розширення `vacancy_alert_subscriptions` (city, salary_min, salary_max, employment_type, is_remote)

## ФАЗА 3 — Роботодавець: керування через бот

**Мета:** дати paying customers повноцінні інструменти керування з мобільного без переходу на сайт.

**Складність:** Середня
**Ефект:** 🟢🟢🟢 Розгрузка сайту, 🟢🟢 Монетизація, 🟢🟢 Конкурентна перевага

### 3.1. Розширення «нова заявка» сповіщення
**Зараз:** простий текст
**Стає:** текст + інлайн кнопки:
- `📄 Переглянути CV` (deep link на сайт)
- `✅ Запросити на співбесіду` → одразу шле async-interview request з preset-питаннями з вакансії
- `❌ Відхилити` → шле кандидату стандартну відмову з template → `editMessageText`
- `💬 Написати` → відкриває чат на сайті

### 3.2. `/vacancies` — мої вакансії
- Список активних з summary: відгуків / переглядів / днів до закінчення
- Inline по кожній:
  - «➕ Продовжити» (15/30/90 днів)
  - «📥 Архівувати»
  - «🔥 Зробити Hot»
  - «⬆ Зробити Top»
- **Монетизація:** кнопки Hot/Top → LiqPay deep link → автоматичне застосування через webhook

### 3.3. Денний дайджест для роботодавця
- Опційне щоденне повідомлення о 09:00:
  > «📊 Сьогодні: 3 нові відгуки на 2 ваші вакансії, 1 вакансія закінчується через 5 днів»
- Кнопки переходу до конкретних
- Налаштування часу/частоти у `/settings`

### 3.4. Швидкий перегляд кандидатів
- На повідомленні про відгук → button «👥 Всі відгуки на цю вакансію»
- Карусель кандидатів через `editMessageText` + pagination
- Швидкі дії на кожному: shortlist / reject / message
- Фільтри: за статусом, за датою

### 3.5. Команда `/billing` — рахунки та послуги
- Перегляд активних послуг (Hot/Top вакансії, доступи до CV)
- Залишок коштів / період підписки
- Швидка покупка послуг через deep link на LiqPay
- Перегляд останніх інвойсів (особливо для IBAN/MonoPay flow)

## ФАЗА 4 — Інтерактивні діалоги (флагманська фаза)

**Мета:** найсильніший конкурентний відрив. Кандидат може повноцінно проходити співбесіди прямо в Telegram.

**Складність:** Висока
**Ефект:** 🟢🟢🟢 Конкурентна перевага, 🟢🟢🟢 Engagement, 🟢🟢🟢 Розгрузка сайту

### 4.1. Conversational interview у боті
- Коли роботодавець шле interview request → кандидат відповідає **прямо в Telegram**, не на сайті
- Бот веде кандидата через питання послідовно:
  > «Питання 1 з 5: Розкажіть про ваш досвід з Laravel»
- Прийом текстових та голосових відповідей
- **Голосові відповіді** → транскрипція через Whisper API → зберігаються як `InterviewResponse`
- State machine для відстеження прогресу (Redis-based)
- Можливість призупинити та продовжити («/pause», «/resume»)

**Це великий конкурентний відрив — жоден український конкурент так не вміє.**

### 4.2. AI-помічник для пошуку (`/find`)
- Кандидат: «Знайди мені роботу Junior PHP у Києві до 40к гривень, можна remote»
- Парсинг через LLM (Claude API) → виклик пошукового API → топ-3 вакансії з кнопками
- Можна обмежити N запитів/день безкоштовно → монетизація через преміум

### 4.3. AI-аналіз резюме (платна функція)
- Кандидат шле резюме у бот → AI feedback:
  - Слабкі сторони
  - Відсутні метрики досягнень
  - Рекомендації по покращенню
  - Аналіз відповідності до конкретних вакансій
- Платна функція — окрема монетизація

### 4.4. Скринінгові запитання для роботодавця
- При відгуку бот автоматично питає кандидата 1-3 скринінгові питання (заданих в вакансії)
- Відповіді приходять разом з відгуком у пакеті
- Роботодавець бачить відразу відсіяних кандидатів

### Артефакти Фази 4
- Інтеграція з Whisper API (транскрипція)
- Інтеграція з Anthropic Claude API (NLP, AI-аналіз)
- Нові таблиці: `interview_bot_sessions`, `screening_questions`, `screening_answers`
- `BotInterviewStateMachine` сервіс
- Окремий queue для AI-обробки (можливо повільні відповіді)

## Технічний фундамент (наскрізні рішення)

### Архітектура callback flow
```
Telegram Bot (Python) → /api/telegram/webhook (Laravel)
                                ↓
                     TelegramCallbackRouter
                                ↓
                  Dispatch to specific Handler
                                ↓
              Business logic (Service layer)
                                ↓
                 TelegramNotifier.editMessage()
                                ↓
                     Update in Telegram
```

### Захист callback_data
- HMAC-підпис у форматі: `action:resource:id:param:signature`
- Перевірка `user_id` з callback proти `telegram_id` у БД
- Rate limiting через Redis (max 30 callbacks/min на user)

### Conventions
- Усі handlers через interface `TelegramCallbackHandlerInterface`
- Усі команди через interface `TelegramCommandHandlerInterface`
- Single source of truth для текстів повідомлень (i18n-ready, UA-first)
- Тести: feature-тести з mock Telegram API (як у вже існуючих модулях)

## Залежності та ризики

### Зовнішні залежності
- **Telegram Bot API** — основний канал; ризики rate limiting (зараз 30 msg/sec до одного користувача)
- **Whisper API** (Фаза 4.1) — транскрипція голосу; вартість $0.006/хв
- **Anthropic Claude API** (Фаза 4.2-4.3) — NLP та AI-аналіз; контроль вартості через rate limits

### Технічні ризики
- **Python bot ↔ Laravel sync:** потрібна надійна черга (Redis Streams або RabbitMQ) для callback-обробки
- **State management** для multi-step flows (Фаза 4.1): зараз stateless, потрібен Redis-based state machine
- **HMAC keys rotation:** план на ротацію без розриву існуючих callback кнопок

### Бізнес-ризики
- **Privacy:** push-сповіщення мають бути opt-in за замовчуванням (особливо 2.5)
- **Spam:** rate limiting на bot-side щоб уникнути abuse
- **Юридичні нюанси:** AI-аналіз резюме (4.3) має чітко позиціонуватись як рекомендація, не оцінка
