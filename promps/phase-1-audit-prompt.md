## 🔍 КРОК 1 — Інвентаризація через git

### 1.1. Знайти точку до Фази 1
Знайти hash коміту/гілки **до** початку Фази 1. Можливі стратегії:
- Якщо Фаза 1 робилась в окремій гілці — `git log main..HEAD`
- Якщо в main — знайти коміт `before` за датою / повідомленням ("phase 1", "telegram bot infrastructure", тощо)

Зафіксувати:
```
BASE_REF=<hash коміту до Фази 1>
HEAD_REF=<поточний HEAD>
```

### 1.2. Список усіх змінених/видалених тест-файлів
```bash
git diff --name-status $BASE_REF..$HEAD_REF -- tests/
```

Згрупувати за статусом:
- **D (Deleted)** — повністю видалені файли
- **M (Modified)** — змінені файли
- **A (Added)** — нові файли (очікувано: 3 нові test-файли з Фази 1)
- **R (Renamed)** — перейменовані

### 1.3. Інвентаризація змінених production-файлів
```bash
git diff --name-status $BASE_REF..$HEAD_REF -- app/ config/ routes/ database/
```

Особлива увага:
- Видалені контролери / сервіси / моделі
- Зміни в `routes/web.php` та `routes/api.php`
- Зміни в міграціях (якщо є — це червоний прапор, бо в скоупі Фази 1 міграції не планувалися)

## 🔍 КРОК 2 — Аналіз кожного видаленого тесту

Для **кожного** видаленого тест-методу (а не тільки файлу) перевірити:

### 2.1. Виправдане видалення
Тест перевіряв **deprecated/видалену поведінку**, яка:
- більше не існує в коді
- замінена іншим механізмом (Volt-компонент білінгу замість extend-controller)
- з memory / документації відомо що це навмисне видалення (Stripe)

**Маркер:** ✅ OK to delete

### 2.2. Перенесене покриття
Тест перевіряв поведінку, яка **досі існує**, але:
- покрита іншим (новим або існуючим) тестом
- покриття мігрувало в інший test-файл

**Дія:** Знайти **конкретний** тест, який тепер покриває цю поведінку. Назвати файл і метод.

**Маркер:** ✅ Coverage moved → `tests/.../NewTestFile.php::method_name`

### 2.3. ⚠️ Втрачене покриття
Тест перевіряв поведінку, яка **досі існує в коді**, але **жоден інший тест її не перевіряє**.

**Це проблема.** Потрібно або:
- Відновити тест (адаптувати під новий код)
- Свідомо прийняти втрату покриття (з обґрунтуванням)

**Маркер:** ❌ Coverage gap → опис який функціонал залишився без тестів

### 2.4. Як перевіряти "Coverage moved" vs "Coverage gap"
Для кожного видаленого тесту:
1. Прочитати оригінальний код тесту через `git show $BASE_REF:tests/.../TestFile.php`
2. Зрозуміти що саме він перевіряв (assertion → endpoint/method)
3. Перевірити чи поведінка ще існує в production коді
4. Якщо існує — `grep` по решті тестів на пошук схожих assertions
5. Висновок: ✅ OK / ✅ Moved / ❌ Gap
