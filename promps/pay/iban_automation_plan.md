# План автоматизації оплати через IBAN (Monobank API)

Цей документ описує технічний процес інтеграції оплати за реквізитами IBAN у систему на базі Laravel.

---

## 1. Підготовчий етап
* **Отримання API-токену:** Авторизація на [api.monobank.ua](https://api.monobank.ua/) та отримання `X-Token`.
* **Налаштування оточення:** Додавання ключів у `.env`:
    ```env
    MONO_TOKEN=your_token_here
    MONO_ACCOUNT_ID=your_account_id
    ```
* **Міграції БД:** Додавання в таблицю `orders` полів `payment_id` (string, unique) та `status` (enum).

## 2. Формування рахунку (Frontend + Backend)
* **Генерація ID замовлення:** Створення запису в БД зі статусом `pending`.
* **Створення призначення платежу:** Формат: `Оплата замовлення №[ORDER_ID]`.
* **QR-код (EPC Standard):** Генерація QR-коду, що містить:
    * Назву отримувача та ЄДРПОУ.
    * IBAN рахунку.
    * Суму в UAH.
    * Призначення з ID замовлення.

## 3. Налаштування Webhook
* **Реєстрація URL:** Одноразовий запит до `POST /personal/webhook` для реєстрації вашого API-endpoint.
* **Endpoint в Laravel:** Створення контролера для прийому POST-запитів від банку.
* **Безпека:** Перевірка токена банку в заголовках запиту.

## 4. Обробка та активація (Логіка)
* **Парсинг:** Використання Regex для пошуку номера замовлення в полі `description` виписки.
* **Валідація:**
    * Перевірка відповідності суми (враховуючи конвертацію копійок у гривні).
    * Перевірка на дублікати (чи не оброблявся цей `statement_id` раніше).
* **Активація:** Зміна статусу замовлення на `paid` та надання доступу до тарифу.

## 5. Резервне копіювання (Cron Polling)
* **Scheduled Task:** Створення консольної команди Laravel, яка раз на 30 хвилин перевіряє виписку через `GET /personal/statement`.
* **Мета:** Обробка платежів, якщо Webhook не був доставлений через технічні збої.
