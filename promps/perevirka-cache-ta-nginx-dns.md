## Крок 2 — Виправлення #1: інвалідація кешу ціни (тільки якщо ПІДТВЕРДЖЕНО)

Скидати кеш на рівні **model event**, а не лише в дії Filament — щоб покрити будь-який шлях зміни ціни (Filament, seeder, tinker, майбутній код).

У `AddonSettings::booted()` (або `boot()` за наявним стилем проєкту) додай хук, що скидає кеш ціни після збереження:

```php
protected static function booted(): void
{
    static::saved(function (AddonSettings $settings): void {
        // Використай ТОЧНИЙ ключ(і) з Кроку 1.
        // Якщо ключ окремий на кожен тип:
        Cache::forget("addon_price_{$settings->type->value}");
        // Якщо ключ один на всі типи — forget цього єдиного ключа.
    });
}
```

Вимоги:
- НЕ змінюй сигнатуру/логіку `AddonType::price()` — лише гарантуй, що після `forget` наступний виклик перечитає з БД.
- Використай реальну назву ключа з розвідки, не вигадуй.
- Якщо в проєкті використовуються cache tags — застосуй flush за тегом замість поіменного forget.

## Крок 4 — Виправлення #2: nginx re-resolve через runtime DNS (тільки якщо ПІДТВЕРДЖЕНО)

Корінь 502 після rebuild — nginx резолвить upstream-хост **один раз на старті** й тримає старий IP контейнера. Лікується винесенням upstream у змінну + `resolver` вбудованого DNS Docker (`127.0.0.11`), щоб резолв відбувався в рантаймі.

У відповідному `server`/`location`-блоці (адаптуй під реальну директиву з Кроку 1):

**Якщо PHP-FPM (`fastcgi_pass`):**
```nginx
resolver 127.0.0.11 valid=10s;
set $upstream_php <hostname_сервісу>:9000;   # напр. php-fpm:9000 — БЕЗ http://
fastcgi_pass $upstream_php;
```

**Якщо HTTP-upstream (`proxy_pass`):**
```nginx
resolver 127.0.0.11 valid=10s;
set $upstream_app http://<hostname_сервісу>:8080;   # зі схемою http://
proxy_pass $upstream_app;
```

Критично:
- Саме **змінна** в `set` змушує nginx перерезолвити IP; без неї `resolver` не допоможе.
- `fastcgi_pass` — **без** `http://`; `proxy_pass` — **зі** `http://`.
- Підстав реальний hostname сервісу з `docker-compose.yml` (Крок 1, п.7).
- Не чіпай решту конфіга.
