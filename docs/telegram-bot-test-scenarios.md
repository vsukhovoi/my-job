# Сценарій перевірки Telegram Бота

## Передумови

| # | Умова |
|---|-------|
| 1 | `.env` містить `TELEGRAM_TOKEN`, `TELEGRAM_WEBHOOK_URL` |
| 2 | Webhook зареєстровано: `php artisan nutgram:set-webhook` |
| 3 | Черги запущено: `php artisan queue:work` |
| 4 | Redis доступний |
| 5 | У БД є хоча б одна категорія, одна вакансія (`is_active=true`), один юзер-роботодавець з `telegram_id` |

---

## Блок 1 — Авторизація через бота (`/start auth_*`)

**Мета:** кандидат авторизується на сайті через Telegram без паролю

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 1.1 | Відкрити сторінку входу → натиснути "Увійти через Telegram" | `POST /api/telegram/auth/init` повертає `session_token` + deep link `t.me/BOT?start=auth_TOKEN` |
| 1.2 | Перейти по deep link у Telegram | Бот надсилає кнопку "Поділитися контактом" |
| 1.3 | Натиснути кнопку та поділитися номером телефону | `ContactAuthHandler` обробляє контакт → бот відповідає "Авторизація успішна" |
| 1.4 | Повернутись на сторінку сайту (або дочекатись polling) | `GET /api/telegram/auth/status/{token}` → `status: authorized` → редірект у кабінет |
| 1.5 | Перевірити БД | `telegram_sessions` запис: `status=authorized`, `telegram_id` заповнено; у `users` — `telegram_id` прив'язано |

**Негативний кейс:**
- Перейти по протермінованому deep link (після 5 хвилин) → бот відповідає помилкою, сесія `expired`

---

## Блок 2 — Прив'язка акаунту (`/start link_*`)

**Мета:** вже зареєстрований юзер прив'язує Telegram

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 2.1 | Авторизуватись на сайті → перейти в налаштування → натиснути "Прив'язати Telegram" | Генерується `link_TOKEN`, з'являється deep link |
| 2.2 | Перейти по посиланню в Telegram | `StartCommand` розпізнає префікс `link_` → знаходить юзера за токеном → зберігає `telegram_id` у `users` |
| 2.3 | Перевірити БД | `users.telegram_id` = `chat_id` бота |

---

## Блок 3 — Перегляд вакансії (`/start job_*`)

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 3.1 | Сформувати посилання `t.me/BOT?start=job_{vacancy_id}` | |
| 3.2 | Перейти по посиланню | Бот надсилає картку вакансії з кнопкою "Переглянути" → посилання на `/jobs/{slug}` |
| 3.3 | Вакансія неіснуюча (id=99999) | Бот відповідає повідомленням "Вакансія не знайдена" (без крашу) |

---

## Блок 4 — Підписки на сповіщення (`/alerts`)

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 4.1 | Надіслати `/alerts` боту | Бот відправляє inline keyboard зі списком категорій (назва + чекмарк якщо підписаний) |
| 4.2 | Натиснути на категорію (не підписаний) | `AlertToggleCallback` → `telegram_subscriptions` запис додано → повідомлення оновлено, з'явився ✅ |
| 4.3 | Натиснути ще раз (вже підписаний) | Запис видалено → ✅ прибрано |
| 4.4 | Перевірити rate limit | 31 callback за хвилину → відповідь "Занадто багато запитів" |

---

## Блок 5 — Сповіщення роботодавцю про нову заявку

**Передумова:** роботодавець має `telegram_id`, вакансія активна, кандидат подає заявку

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 5.1 | Кандидат подає заявку на вакансію | `SendNewApplicationNotification` поставлено в чергу |
| 5.2 | Черга обробляє Job | Роботодавець отримує Telegram повідомлення з кнопками: "CV", "Запросити", "Відхилити", "Написати" |
| 5.3 | Роботодавець натискає "Запросити" | `InviteToInterviewHandler` → `application.status = interview` → кандидат отримує email/Telegram сповіщення |
| 5.4 | Роботодавець натискає "Відхилити" | `RejectApplicationHandler` → `application.status = rejected` → сповіщення кандидату |
| 5.5 | Перевірити підпис callback | Підмінити `signature` в callback → `TelegramCallbackRouter` відхиляє (403) |

---

## Блок 6 — Сповіщення кандидату про зміну статусу

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 6.1 | Роботодавець змінює статус заявки вручну в дашборді | `SendApplicationStatusNotification` поставлено в чергу |
| 6.2 | Черга обробляє Job | Кандидат отримує повідомлення в Telegram (якщо `telegram_id` є) |
| 6.3 | Кандидат без `telegram_id` | Fallback на email — жодного краша |

## Блок 7 — Масова розсилка вакансій (`app:send-vacancy-alerts`)

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 7.1 | Підписати тест-акаунт на категорію (Блок 4) | |
| 7.2 | Опублікувати вакансію в цій категорії | `published_at` = зараз |
| 7.3 | `php artisan app:send-vacancy-alerts` | Кожен підписаний акаунт отримує повідомлення з назвою вакансії + посиланням |
| 7.4 | Запустити повторно відразу | Повторне повідомлення НЕ надсилається (вакансія більше не в "останній годині" або вже оброблена) |

---

## Блок 8 — Сповіщення про закінчення вакансії

| Крок | Дія | Очікуваний результат |
|------|-----|----------------------|
| 8.1 | Створити вакансію з `published_at` = 23 год. тому | |
| 8.2 | `php artisan app:notify-expiring-vacancies --hours=24 --dry-run` | Виводить список вакансій без відправки |
| 8.3 | Без `--dry-run` | Роботодавець отримує Telegram/email сповіщення про закінчення |

---

## Блок 9 — Безпека та граничні кейси

| Тест | Очікуваний результат |
|------|----------------------|
| `POST /telegram/webhook` без підпису Telegram | 403 / ігнорування |
| `POST /api/telegram/webhook/callback` без `X-Telegram-Webhook-Token` | 401 |
| Callback з невалідним HMAC | `TelegramCallbackRouter` → відмова, логування |
| `GET /api/telegram/auth/status/{token}` — 121-й запит за хвилину | Rate limit 429 |
| Deep link `auth_` — після 5 хвилин | Redis ключ expired → "Посилання застаріло" |
